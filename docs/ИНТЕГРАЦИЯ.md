# Инструкция по подключению бронирования и оплаты

**Проект:** сайт отеля Airis Residence — https://airisresidence.kz
**Юрлицо:** ТОО «INCOME HOUSE», БИН 200640012670
**Кому этот документ:** банку-эквайеру, поставщику системы бронирования или подрядчику, который будет их подключать.

Сайт уже полностью готов и работает. Кнопки «Забронировать» есть на всех страницах и ведут на форму заявки. Чтобы они начали вести на настоящую онлайн-бронь и оплату, **править код не нужно** — достаточно заполнить переменные окружения. Ниже расписано, какие именно.

---

## Кратко: что нужно от вас

Пришлите **одно из двух** (или оба, если система бронирования и эквайринг — разные поставщики):

| Что | Куда мы это вставим |
|---|---|
| **Ссылка** на страницу бронирования/оплаты | `NEXT_PUBLIC_BOOKING_URL` |
| **Код виджета** (`<script src=...>` + контейнер `<div>`) | `NEXT_PUBLIC_BOOKING_WIDGET_SRC` и `NEXT_PUBLIC_BOOKING_WIDGET_HTML` |
| Доступы к эквайрингу: `client_id`, `client_secret`, `terminal_id`, адрес API, секрет подписи | Переменные `PAYMENT_*` на бэкенде |

И **примите от нас** адрес для колбэка об оплате:

```
https://<домен-бэкенда>/api/payments/callback
```

## Вариант А. У вас есть ссылка на бронирование

Самый простой путь. Подходит, если поставщик даёт готовую страницу бронирования (TravelLine, Bnovo, Exely, OtelMS, страница оплаты банка и т. п.).

**Файл:** `frontend/.env.local` (на хостинге — переменные окружения проекта)

```bash
NEXT_PUBLIC_BOOKING_MODE=engine
NEXT_PUBLIC_BOOKING_URL=https://ваша-ссылка-на-бронирование
```

После этого все кнопки «Забронировать» на сайте начнут открывать эту ссылку в новой вкладке.

### Передача параметров в ссылку

Сайт умеет добавлять к ссылке даты, количество гостей и тип номера — гость попадает на движок с уже заполненной формой. Названия параметров у всех поставщиков разные, поэтому их можно настроить:

```bash
NEXT_PUBLIC_BOOKING_PARAM_CHECKIN=checkin     # дата заезда, формат YYYY-MM-DD
NEXT_PUBLIC_BOOKING_PARAM_CHECKOUT=checkout   # дата выезда, формат YYYY-MM-DD
NEXT_PUBLIC_BOOKING_PARAM_ADULTS=adults       # количество гостей, число
NEXT_PUBLIC_BOOKING_PARAM_ROOM=room           # код типа номера
```

**Пример.** Если движок ждёт ссылку вида
`https://booking.example.com/airis?arrival=2026-08-20&departure=2026-08-22&guests=2`,
то настройки будут такие:

```bash
NEXT_PUBLIC_BOOKING_URL=https://booking.example.com/airis
NEXT_PUBLIC_BOOKING_PARAM_CHECKIN=arrival
NEXT_PUBLIC_BOOKING_PARAM_CHECKOUT=departure
NEXT_PUBLIC_BOOKING_PARAM_ADULTS=guests
```

### Коды типов номеров

Сайт передаёт вот такие коды. Сопоставьте их со своими кодами на стороне движка:

| Код на сайте | Название | Площадь | Цена/ночь |
|---|---|---|---|
| `standart-single` | Standart Single | 16–18 м² | 25 000 ₸ |
| `standart` | Standart | 18–20 м² | 45 000 ₸ |
| `standart-twin` | Standart Twin | 23 м² | 45 000 ₸ |
| `comfort` | Comfort | 25 м² | 50 000 ₸ |
| `luxe` | Luxe | 30 м² | 70 000 ₸ |

Если у вас другие коды — либо пришлите таблицу соответствия, либо мы поменяем `slug` в файле `frontend/lib/site.ts` на ваши.

## Вариант Б. У вас есть код виджета

Подходит, если поставщик даёт вставку скриптом.

```bash
NEXT_PUBLIC_BOOKING_MODE=widget
NEXT_PUBLIC_BOOKING_WIDGET_SRC=https://cdn.поставщик.kz/widget.js
NEXT_PUBLIC_BOOKING_WIDGET_HTML=<div id="booking-widget" data-hotel="airis"></div>
```

Виджет отрисуется на странице **https://airisresidence.kz/bronirovanie** — в блоке, который для него уже подготовлен (`frontend/components/booking/BookingWidgetSlot.tsx`).

> Скрипт загружается стратегией `afterInteractive` — после отрисовки страницы, чтобы не тормозить загрузку сайта.

## Вариант В. Полноценный эквайринг через наш бэкенд

Нужен, если платёж проводится нашим сервером, а не отдельной страницей поставщика: гость платит на сайте, деньги идут на расчётный счёт ТОО «INCOME HOUSE» в ForteBank.

### Что заполняет банк

**Файл:** `backend/.env`

```bash
PAYMENT_PROVIDER=epay_halyk        # или fortebank
PAYMENT_BASE_URL=                  # адрес API банка
PAYMENT_TERMINAL_ID=               # идентификатор терминала
PAYMENT_CLIENT_ID=                 # client_id из личного кабинета
PAYMENT_CLIENT_SECRET=             # client_secret
PAYMENT_WEBHOOK_SECRET=            # секрет для проверки подписи колбэка

PAYMENT_SUCCESS_URL=https://airisresidence.kz/oplata/uspeh
PAYMENT_FAILURE_URL=https://airisresidence.kz/oplata/oshibka
```

> ⚠️ Секреты передавайте не письмом и не в мессенджере, а через защищённый канал (менеджер паролей, конверт). В коде и в git их нет и быть не должно.

### Что уже реализовано с нашей стороны

Файл `backend/app/payments.py` — каркас интеграции. В нём три метода, которые интегратору нужно сверить с документацией банка и при необходимости поправить:

| Метод | Что делает | Что проверить |
|---|---|---|
| `get_token()` | Получает OAuth-токен | URL и список scope |
| `create_payment()` | Создаёт платёж, возвращает ссылку на оплату | Адрес метода и имена полей в теле запроса |
| `verify_callback()` | Проверяет подпись колбэка | Алгоритм подписи (обычно HMAC по телу) |
| `parse_callback()` | Разбирает статус из колбэка | Названия полей `invoiceId` / `code` |

Каркас написан под протокол Halyk ePay 2.0 как наиболее распространённый в РК. Для ForteBank класс наследуется от него — если протокол расходится, переопределяются те же методы, остальной код трогать не нужно.

### Готовые эндпоинты

| Метод | Адрес | Назначение |
|---|---|---|
| `POST` | `/api/payments/init` | Создать платёж, получить ссылку на оплату |
| `POST` | `/api/payments/callback` | **Колбэк банка** об оплате (postLink / webhook) |
| `GET` | `/api/payments/{order_id}` | Проверить статус платежа |
| `GET` | `/health` | Проверка живости и того, настроен ли шлюз |

**Адрес колбэка, который нужно прописать в личном кабинете банка:**

```
https://<домен-бэкенда>/api/payments/callback
```

Пример запроса на создание платежа:

```http
POST /api/payments/init
Content-Type: application/json

{
  "amount": 45000,
  "description": "Проживание в отеле Airis Residence, номер Standart",
  "email": "guest@example.com",
  "phone": "+77771234567",
  "lead_id": 12
}
```

Ответ:

```json
{
  "order_id": "a1b2c3d4e5f6a7b8c9d0",
  "payment_url": "https://epay.bank.kz/payform/...",
  "status": "pending"
}
```

Сумма передаётся **в тенге**; в базе хранится в тиынах (×100), чтобы не терялись копейки при возвратах.

### Как проверить, что всё подключилось

```bash
curl https://<домен-бэкенда>/health
```

```json
{ "status": "ok", "payments_configured": true, "telegram_configured": true }
```

`payments_configured: true` — шлюз подхватил настройки. Пока `false`, эндпоинты оплаты отвечают `501 Not Implemented`, и это **штатное поведение**, а не ошибка: сайт продолжает принимать заявки через форму.

## Пока ничего не подключено

Сайт полностью рабочий. Кнопка «Забронировать» ведёт на страницу `/bronirovanie` с формой заявки. Заявка уходит:

1. в Telegram — мгновенное уведомление администратору;
2. в базу данных — если поднят бэкенд.

Настраивается это в `frontend/.env.local`:

```bash
TELEGRAM_BOT_TOKEN=токен от @BotFather
TELEGRAM_CHAT_ID=id чата, узнать у @userinfobot
```

Так что переключение на онлайн-оплату — не «запуск сайта», а спокойное добавление одной строки в настройки.

## Место под 3D-тур

Отдельно от бронирования на главной странице есть блок под панорамный тур по отелю. Подключается тоже одной переменной:

```bash
NEXT_PUBLIC_TOUR_3D_URL=https://ссылка-на-тур
```

Подойдёт любой встраиваемый тур: Kuula, Matterport, Pannellum, собственный плеер. Пока ссылки нет — на этом месте аккуратная заглушка, дырки на сайте не видно.
