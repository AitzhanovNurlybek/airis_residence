# Подключение API Exely

Что делать в кабинете Exely, что прислать разработчику и что произойдёт после.
Обновлено 2026-08-24.

## Где мы сейчас

| | Состояние |
|---|---|
| Кабинет Exely | получен, `secure.exely.kz` |
| Раздел «Подключения API» | доступен, список пуст |
| Чтение наличия | **работает** — с открытого адреса виджета брони |
| Запись брони | нет, для неё и нужно подключение |

Поддержка Exely (Аида Максотова, +7 771 743 0390) подтвердила: API формы
бронирования есть. **Условие одно — форма должна вести гостей на форму
бронирования Exely.** Мы это условие выполняем: сайт и так открывает их
форму, а помощник в переписке будет доводить гостя до неё же.

## Шаг 1. Создать подключение

Кабинет → **Настройки гостиницы** → **Подключения API** → **Создать
подключение**.

Что писать в полях, если спросят:

| Поле | Значение |
|---|---|
| Название | `Сайт и ИИ-помощник Airis Residence` |
| Назначение | Показ наличия и цен на сайте, оформление броней из переписки с гостем |
| Кто использует | Отель, собственная разработка |

После создания выдадут ключ или пару «идентификатор + секрет». **Ключ
показывают один раз** — сохраните сразу в менеджер паролей.

## Шаг 2. Что прислать разработчику

Присылать сам ключ в переписке не нужно. Достаточно сообщить, что подключение
создано, и прислать:

- адрес API из документации Exely (обычно указан рядом с ключом);
- какие операции доступны по этому подключению;
- ссылку на документацию, если её дали.

Ключ кладётся в `backend/.env` и в переменные Vercel:

```
EXELY_API_KEY=...
EXELY_BASE_URL=...
BOOKING_SYSTEM=exely
```

Больше ничего менять не придётся: место под эти три строки в коде уже
размечено.

## Шаг 3. Что спросить у поддержки

Эти вопросы решают, что помощник сможет делать, а что останется менеджеру.

1. Какие операции поддерживает подключение: наличие, цены, создание брони,
   изменение, отмена, получение брони по номеру?
2. Есть ли уведомление о том, что бронь изменилась на стороне Exely
   (вебхук)? Без него мы узнаем об отмене только когда сами спросим.
3. Есть ли тестовый контур, чтобы отладить обмен, не трогая боевые брони?
4. Ограничения по частоте запросов — сколько обращений в минуту допустимо?
5. Как в API обозначается источник брони? Хотим, чтобы брони от помощника
   были видны в шахматке отдельной меткой, как `booking.com` или `От стойки`.

Пятый вопрос стоит задать обязательно. В шахматке видно, что каждая бронь
подписана источником; если наши брони придут без метки, менеджер не отличит
их от прочих, и разбираться с ошибкой будет негде.

## Что заработает сразу после подключения

**Помощник начнёт оформлять брони сам.** Сейчас он видит свободные номера, но
запись отдаёт менеджеру заявкой. С ключом бронь встанет в шахматку в момент
разговора — гость в час ночи получит подтверждённый номер, а не обещание
перезвонить утром.

**Наличие станет надёжнее.** Сейчас оно читается с адреса, который Exely нам
не обещала и может изменить без предупреждения. Договорной доступ снимает этот
риск.

**Отмена и перенос из переписки.** Гость пишет «перенесите на неделю позже» —
и это происходит, а не превращается в задачу для стойки.

## Чего подключение не даст

Счета и оплату оно не закрывает: их выставляет отель, и проверка присланных
чеков останется как есть. Корпоративные цены по договору тоже наши — Exely
про них не знает.

- Прогон проверок гоняется одной командой: `ПРОВЕРИТЬ.ps1`.
