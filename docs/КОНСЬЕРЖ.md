# ИИ-консьерж Airis Residence — передача

Для того, кто продолжит работу. Здесь состояние на 2026-08-24, устройство,
правила, о которые я спотыкался, и список задач.

Читать сверху вниз. Раздел «Главные правила» — не философия: каждый пункт там
появился после конкретного бага.

---

## 1. Что это

Автоматический помощник, который переписывается с гостями отеля от лица
отеля. Планируемые каналы — WhatsApp и Instagram; каналов пока нет, есть окно
переписки в админке.

Что он умеет сегодня:

- отвечать про цены, номера, правила заезда, услуги, окрестности — на русском,
  казахском и английском;
- смотреть **настоящее** наличие номеров в Exely;
- оформлять, переносить и отменять брони (в песочнице; в Exely — пока нет);
- читать присланные платёжки и сводить их с бронью;
- передавать разговор человеку там, где не должен решать сам.

Где посмотреть: админка → **Консьерж** (`/admin/shahmatka`). Страница из
четырёх частей, включая окно переписки.

## 2. Быстрый старт

```powershell
.\ЗАПУСТИТЬ.ps1      # поднимает бэкенд и сайт, открывает раздел «Консьерж»
.\ПРОВЕРИТЬ.ps1      # прогоняет все проверки
.\ПРОВЕРИТЬ.ps1 -Fast # только быстрые, без обращений к модели
```

Вручную:

```bash
cd backend  && .venv/Scripts/python.exe -m uvicorn app.main:app --port 8000
cd frontend && npm run dev          # обязательно порт 3000
```

**Порт 3000 обязателен.** В `backend/.env` лежит `SITE_URL=http://127.0.0.1:3000`
— оттуда консьерж берёт справку об отеле. Запустите на 3001, и он будет честно
отвечать «не могу свериться с ценами». Выглядит как поломка помощника, а дело
в порте.

### Проверки

| Файл | Что проверяет | Стоимость |
|---|---|---|
| `backend/e2e_qa.py` | 103 проверки без модели: разбор ответов Exely, даты, режимы, права | секунды, бесплатно |
| `backend/e2e_concierge.py` | справку, инструменты, поведение при сбоях | один вызов модели |
| `backend/e2e_payment.py` | разбор платёжек, квитанции рисуются в самом тесте | ~8 вызовов |
| `backend/e2e_dialog.py` | 21 живой диалог целиком | ~40 вызовов, заметные деньги |
| `scripts/e2e_corp_live.sh` | кабинет компаний и публичный сайт | бесплатно |

Гоняйте `e2e_qa.py` постоянно, `e2e_dialog.py` — перед выпуском.

## 3. Как устроено

### Три части и одна мысль

```
frontend/app/api/knowledge/route.ts   факты об отеле  ─┐
backend/app/knowledge.py              загрузка + бриф ─┼→ backend/app/concierge.py
backend/app/booking_system/           наличие и брони ─┘   правила и вызов модели
```

**Мысль одна: копий фактов не существует.** Цены, правила заезда и услуги
консьерж берёт с `/api/knowledge`, а тот собирает их из тех же модулей, из
которых сайт рисует страницы. Поменяли цену в админке — консьерж узнаёт тогда
же, когда и сайт.

Это не чистоплюйство. Цена, названная гостю в переписке, — обещание отеля.
Собственная копия прайса отстаёт при первой же правке, и однажды консьерж уже
называл 25 000 за номер, который стоит 35 000.

### Система бронирования — подменяемая часть

`backend/app/booking_system/` — один интерфейс и несколько реализаций.
Переключается строкой `BOOKING_SYSTEM` в `backend/.env`:

| Значение | Наличие | Запись | Когда |
|---|---|---|---|
| пусто | нет | нет | наличие подтверждает стойка |
| `exely` | **настоящее** | нет | только смотреть |
| `hybrid` | **настоящее** | заявка менеджеру | **готово к боевому**, выключено |
| `local` | своя база | своя база | отладка записи |
| `stub` | хеш, без базы | нет | быстрые проверки |

Файлы: `base.py` (договор), `exely.py` (настоящий), `hybrid.py`,
`local.py` (песочница), `stub.py`, `__init__.py` (выбор режима).

### Откуда берётся настоящее наличие

Из открытого адреса, куда ходит виджет брони на страницах сайта:

```
GET https://kz-ibe.hopenapi.com/ApiWebDistribution/BookingForm/hotel_availability
    ?criterions[0].adults=2
    &criterions[0].dates=ГГГГ-ММ-ДД;ГГГГ-ММ-ДД
    &criterions[0].hotels[0].code=509506
```

Заголовки `Referer` и `Origin` — `https://airisresidence.kz`.

Точные остатки лежат в `room_type_quotas` (`rph` → `quantity`). В самих
`room_stays` есть `limited_inventory_count`, но он приходит только когда
номеров мало — на него одного полагаться нельзя.

Адрес недокументированный. Он может измениться в любой день, поэтому сбой
здесь не роняет ответ гостю: система говорит «не могу свериться» и зовёт
стойку. Записывать через него ничего нельзя и не нужно — для записи есть API,
доступ к которому отель уже получает (см. `EXELY_API.md`).

### Коды Exely

| Код | Категория | На сайте |
|---|---|---|
| 5054709 | Standard single | `standart-single` |
| 5050493 | Standart | `standart` |
| 5050494 | Standart Twin | `standart-twin` |
| 5050496 | Comfort | `comfort` |
| 5050495 | Comfort + | `comfort-plus` |
| 5070642 | Apart | **страницы нет** |

Тарифы: «Выгодные выходные», «Тариф без завтрака», «Best Deal: с завтраком».

## 4. Главные правила

Каждое появилось после бага. Нарушите — получите тот же баг.

### Вердикт выносит код, а не модель

Модель читает и формулирует. Решения о деньгах и правах принимает код —
**до** вызова инструмента, а не просьбой в промпте. Правило в промпте это
просьба, и её достаточно уговорить.

Что вынесено в код:

- **сумму брони считает сервер** по прайсу; модель её не передаёт;
- **чужая бронь не находится** — фильтр по телефону собеседника, который
  приходит из канала, а не из текста. Проверено: посторонний требовал отменить
  чужую бронь, представился владельцем отеля — не вышло;
- **заезд задним числом** отвергает шахматка;
- **оплата**: нет номера брони в назначении → менеджеру; сумма больше
  начисленной → менеджеру; статус «отклонено» → менеджеру.

Первая версия разбора платёжек блокировала оплату по любому замечанию модели —
и она забраковала всё, включая правильные чеки: «нет печати», «нет БИК». Чеки
из мобильных приложений выглядят именно так. Теперь её замечания идут в
заметки менеджеру и ничего не блокируют; блокирует только заявленная правка
изображения.

### Молчаливый запасной вариант — только для показа

Когда база не отвечает, сайт подставляет цены, зашитые в код. Гостю на
странице это спасает вёрстку. Консьержу отдавать нельзя: `/api/knowledge`
в этом случае отвечает 503, и помощник говорит «не могу свериться».

То, что уходит человеку как обещание, не должно подставляться молча.

### Время — только по Алматы

`backend/app/almaty.py`, функция `today()`. **`date.today()` в бизнес-логике
не вызывать.** Сервер в UTC, отель +5: с полуночи до пяти утра сервер считает,
что ещё вчера. Ночная платёжка выглядела датированной завтрашним днём, бронь
на вчера проходила проверку «дата прошла». В `e2e_qa.py` есть проверка, что
`date.today()` не вернулся.

### Отсутствие отчёта — это сбой

В скрипте проверок отсутствие `bash` сначала засчитывалось как успех: зелёная
галочка там, где набор не запускался. Молчаливое «всё хорошо» опаснее
честного «не проверено».

### Заглушка обязана называть себя заглушкой

Пока данные ненастоящие, они должны выглядеть ненастоящими. В режимах `local`
и `stub` консьерж обязан приписывать «это тестовые данные». Привыкнуть к
красивому ответу легко, отличить его потом от боевого — уже нет.

## 5. Что предстоит

По убыванию пользы.

### 5.1. Подключить API Exely — как только придёт ключ

Отель получает доступ, порядок в `docs/EXELY_API.md`. Что делать:

1. Положить в `backend/.env` и в переменные Vercel:
   `EXELY_API_KEY`, `EXELY_BASE_URL`, `BOOKING_SYSTEM=exely`.
2. Заполнить в `backend/app/booking_system/exely.py` методы записи:
   `create_booking`, `change_booking`, `cancel_booking`, `get_booking`.
   Сигнатуры уже описаны в `base.py` — держитесь их, тогда остальной код
   менять не придётся.
3. Проверить `e2e_qa.py`: раздел «Режимы» ждёт, что `exely` не умеет писать —
   это ожидание нужно будет обновить.
4. **Просить у поддержки метку источника.** В шахматке каждая бронь подписана
   (booking.com, «От стойки»). Наши должны приходить со своей меткой, иначе
   менеджер не отличит их от прочих.

После этого гибридный режим можно выключить: заявки станут бронями сразу.

### 5.2. Каналы: WhatsApp и Instagram

Движок разговора от канала не зависит — канал только приносит текст и уносит
ответ. Нужно:

- **WhatsApp через Green API.** У владельца есть опыт с ним по другому проекту
  (`almaty-leads-agent`). Нужен прогретый номер и тариф Business.
- **Instagram через Meta Graph API.** Нужно приложение Meta и бизнес-аккаунт,
  привязанный к странице Facebook.
- Вебхук на входящее сообщение → `concierge.answer(...)` → отправка ответа.
- В `guest` передавать телефон из канала. **Это не мелочь**: по нему решается,
  чьи брони видны.

### 5.3. Хранение диалогов

Сейчас история живёт у вызывающего: в окне админки — в памяти вкладки. Для
каналов нужна таблица: собеседник, канал, сообщения, время. Иначе гость,
написавший через час, начнёт разговор с нуля.

Глубина истории настраивается — `concierge_history_depth`, по умолчанию 12
сообщений.

### 5.4. Файлы из переписки

Гость присылает чек прямо в чат. Разбор готов (`payment_docs.py`, работает из
`scan_payment.py` и со страницы «Консьерж»), не хватает приёма файла из канала
и передачи в тот же разбор.

### 5.5. Уведомления менеджеру

Ни один канал уведомлений не подключён. Заявка от консьержа ложится в базу и
видна в админке, но никто об этом не узнаёт, пока не откроет страницу. Нужно
хотя бы одно: Telegram-бот (поля в настройках уже есть), почта или WhatsApp.

Особенно важно для эскалаций: жалоба, групповая заявка, просьба о скидке.

### 5.6. Мелкое, но полезное

- **Apart на сайт.** Отель продаёт его за 45 000 через агрегаторы с комиссией,
  а собственный сайт про него молчит. Нужны фото, описание, площадь.
- **Число комнат в песочнице** для Comfort+ и Apart — оценка; уточнить по
  шахматке и поправить на странице «Консьерж».
- **Сброс кеша справки.** `knowledge.py` держит факты 10 минут на процесс.
  После правки цен в админке консьерж узнаёт о ней с задержкой. На Vercel
  процессов много, общего сброса нет.
- **Метрики.** Сколько разговоров, сколько дошло до брони, где чаще всего
  зовут человека. Сейчас не считается ничего.

## 6. Грабли

Список нужен, чтобы вы не потеряли на них время.

**Кэш сборки Next.** `getRooms()` кэширует ответ бэкенда на час. Соберёте
фронтенд при выключенном бэкенде — в сборку запечётся запасной прайс из кода,
и он проживёт час. Ловил это четыре раза. Перед проверкой цен:
`rm -rf frontend/.next`. В админке теперь есть красная плашка, когда это
происходит.

**Старые процессы на портах.** Второй `next start` на занятом порту молча
уходит на 3001, а отвечать продолжает старая сборка. Тесты при этом «проходят»
на позапрошлых данных. `ЗАПУСТИТЬ.ps1` и `ПРОВЕРИТЬ.ps1` гасят порты сами.

**Экранирование в цепочке инструментов.** Если правите файлы скриптом через
несколько слоёв кавычек, `\n` и `\b` съедаются и превращаются в настоящий
перенос строки или backspace. Собирайте такие последовательности из
`chr(92)`.

**PowerShell 5.1 и кириллица.** Файл `.ps1` без BOM читается как ANSI:
кириллица превращается в мусор и рвёт кавычки, скрипт не разбирается вовсе.
Сохранять в UTF-8 **с BOM**.

**Telegram-подобные ловушки в Next 16.** `middleware.ts` переименован в
`proxy.ts`. Ссылки `next/link` на маршруты, которые ставят куку и
перенаправляют, вызывают шторм предзагрузки — для таких только обычный `<a>`.

**Словарь кабинета обязан быть сериализуемым.** Функции внутри словаря ломают
границу «сервер → клиент» с ошибкой 500. Формы множественного числа — данными,
склейка — хелпером.

## 7. Доступы и где что лежит

| Что | Где |
|---|---|
| Ключ Anthropic | `backend/.env`, `ANTHROPIC_API_KEY` |
| Боевые доступы отеля | `backend/.env.vercel` (вне git) |
| Кабинет Exely | `secure.exely.kz`, отель 509506 |
| Поддержка Exely | Аида Максотова, +7 771 743 0390 (WhatsApp) |
| База локально | `backend/airis.db` (SQLite) |
| База боевая | Supabase, регион Сидней |
| Сайт | Vercel, деплой из ветки `main` |

**Важно про боевую базу:** она в Сиднее, функции в Вашингтоне. Один запрос —
около полутора секунд. Это не медленный код, это расстояние; лечится только
переносом региона.

**Локальная база отстаёт.** Перед проверкой цен синхронизируйте:

```bash
curl -s https://airisresidence.kz/api/backend/api/rooms
```

и сверьте с `backend/airis.db`. Я на этом попался: неделю гонял проверки на
ценах трёхмесячной давности.

## 8. С чего начать

1. `.\ЗАПУСТИТЬ.ps1`, зайти в админку → «Консьерж».
2. Написать помощнику пару сообщений в окне переписки. Посмотреть под
   ответами, куда он ходил.
3. `.\ПРОВЕРИТЬ.ps1 -Fast` — увидеть, что проверяется.
4. Прочитать `backend/app/concierge.py` — там правила разговора текстом,
   это самая содержательная часть.
5. Прочитать `backend/app/booking_system/base.py` — договор, вокруг которого
   всё построено.

Комментарии в коде объясняют не «что», а «почему». Если решение выглядит
странным — скорее всего, рядом написано, из-за чего оно такое.
